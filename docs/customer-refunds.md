# 用户退票

登录顾客进入 **My tickets**，在有效订单上点击 **Refund tickets**。确认页列出影片、影院、场次、整单座位、实付票款、退票费和实际到账金额；点击 **Keep my tickets** 不改变订单。确认后原票失效，整单座位恢复可选，退款立即进入模拟钱包。订单详情、Refunds、Wallet history 和 Notices 保留记录。

## 本项目规则

这是课程演示的退票规则，沿用项目改签的时间档，并非所有现实影院通用的政策：

- 距开场至少 12 小时：免费。
- 6 小时至不足 12 小时：收当前实付票款的 5%。
- 30 分钟至不足 6 小时：收 20%。
- 不足 30 分钟或已经开场：不可主动退票。

手续费按整单实付票款以分为单位四舍五入。优惠券订单按优惠后的实付票款计算，已用券不恢复，主动退票不发补偿券。已经收取的改签费不退；改签后的有效新订单仍可按新场次时间退票。暂不支持只退整单中的部分座位。

该订单未完成的改签占座会一起取消；其他独立订单的占座不受影响。退款成功后，其他顾客可以重新购买释放的座位。退款后的订单不能再改签或再次退票。影院主动取消场次的原有全额退票、退累计改签费及补偿券流程保持原规则。

## 已有数据库升级

先停止自己正在运行的网站，在项目根目录执行（使用项目虚拟环境）：

```bash
python -m flask --app cinema:create_app migrate-customer-refunds
```

macOS 未激活虚拟环境时使用：

```bash
.venv/bin/python -m flask --app cinema:create_app migrate-customer-refunds
```

然后重新运行 `main.py` 并刷新网页。命令可以重复执行，不重建数据库，不清空电影、影院、订单、支付或钱包。它只扩展三个状态约束并新增 `booking_cancellations` 审计表。新建空库的 `init-db` 已包含此升级；已有库不要重新 `init-db` 或 `seed-demo`。

代码与迁移工具随 Git 提交，个人 `.env`、数据库数据、备份和密码不提交。组员拉取后需在自己的数据库执行上述命令。

## 接口与一致性

- `POST /api/bookings/<id>/refund-preview`：仅订单所属顾客，返回座位、金额和五分钟有效的签名确认令牌，不退票。
- `POST /api/bookings/<id>/refund`：提交 `preview_token`，必须携带 CSRF 和 `Idempotency-Key`。服务端在取得订单、场次、用户及钱包锁后重新核对状态、截止时间和费用。费用跨档时返回 `PREVIEW_CHANGED`，必须重新预览并再次确认。
- 一次数据库事务记录订单 `CUSTOMER_CANCELLED`、退款 `CUSTOMER_CANCELLATION`、钱包入账、票款冲销、退票手续费、退票明细和通知，并释放原座位及相关改签占座。任何步骤失败全部回滚。
- 原始支付和出票历史不删除。支付结果查询会返回当前票据状态，避免将已退票订单重新显示为有效票。
- 同一请求重试返回原回执；不同请求并发退同一订单只有一次成功。响应中断时确认弹窗保留原令牌和请求键，点击 **Retry this refund** 安全取回结果。
- 模拟钱包退款在确认时完成，不依赖后台 worker。系统没有接真实支付网关，因此不会向银行卡、微信或支付宝发起实际退款。

## 验证

`backend_tests/test_customer_refunds.py` 使用隔离 MySQL 数据库验证费用边界、优惠券、历史改签费、重复和并发请求、权限、CSRF、回滚、座位再售、改签占座清理、影院取消冲突，以及升级重复执行的数据保留。

`tests/browser/refund-smoke.mjs` 仅连接 `scripts/browser_fixture.py` 建立的隔离服务（5002），验证桌面/手机确认页、取消操作、成功退票、响应丢失后重试、余额、可售座位、刷新后状态及退款列表。

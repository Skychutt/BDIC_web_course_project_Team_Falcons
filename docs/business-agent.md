# 业务型影院 Agent：实现与交接

2026-10-24 根据“业务型 Agent 开发思路”调整。网站入口为 `http://127.0.0.1:5001/#/assistant`。

## 当前行为

### 自动跟随提问语言

助手不设语言切换按钮。每轮根据用户问题自动决定回复语言：中文问题用中文，英文问题用英文；只有数字、标点或表情的追问沿用会话上一轮语言。中文问题中的英文片名不会让整句回复变成英文，常见英文提问中的中文片名也可保留。服务端判断优先于客户端传入的 `locale`；`locale` 仅为首次无法判断语言或无提问文字的请求提供默认值。

语言变化不清空对话、筛选条件或候选序号，当前卡片、类型、日期、订单/优惠券状态和操作按钮同步跟随；历史消息保留原文及原始语言标记。浏览器记住上次助手语言以初始化界面，完整主站仍沿用原来的语言。

`cinema_ai/data/translations.json` 保存现有 5 部影片和 6 家影院的双语显示资料，源于当前目录内容的翻译，不新增剧情、上映日期、评分或业务事实。数据库无需迁移。响应附带 `titles / synopses / names / addresses`；ID、价格、评分、排序、可售状态和座位不因语言改变。新增影片未提供译文时保留原文；原简介或地址修改后不继续使用旧译文，应同步维护此文件。私人订单卡片的显示译文仍只在服务端和浏览器处理。

自动判断出的语言同时用于模型回复、缺条件追问、规则、恢复方案和错误反馈；独立 `/assistant` 演示页沿用相同约定。英文卡片发出的 `Show screenings for film number 3` 与中文序号选择走相同的服务端解析路径。双语显示不额外调用模型。

验证：240 项 Python/MySQL 回归、18 项前端测试通过。真实 DeepSeek 浏览器联调完成“中文推荐高分影片 → 英文查询第一部的场次 → 中文补充两个人”，保持同一影片并返回中文连座卡片；独立演示页的英文追问也返回英文。效果见 `output/screenshots/assistant-auto-language.png`。

| 输入 | 实际处理 |
| --- | --- |
| 我想睡觉 | DeepSeek 直接自然回应，零次业务工具调用 |
| 推荐一部电影 | 查询影片目录并展示影片卡片，不要求人数或区域；不擅自增加评分/类型门槛 |
| 最近评分高的科幻电影 | 按已有类型、本站评分与排片查询；优先已有高分，不自动设置分数门槛，附评分人数 |
| 明天朝阳区三个人，每人不超过 50 元 | 日期、区域、人数与预算共同过滤，然后计算座位和排序 |
| 改成两个人 / 第二个 | 合并明确修改的条件；按服务端保存的候选列表解析序号 |
| 我的订单 / 我的优惠券 | 需要顾客登录，只查询当前账号；未登录提供登录入口 |
| 第一个订单能改签吗 | 校验有效状态、开场时间和同影院同影片限制，返回资格及参考费用 |
| 第一场一张普通票一张学生票多少钱 | 复用后端价格计算进行只读预览，不占座、不创建可支付报价、不核销券 |
| 附近最近的影院 | 若地图已配置，提供影院地图入口，由用户主动授权定位；不把设备坐标交给模型 |

没有本站评分的影片不能列入高分结果，因而高分查询可以合法返回空结果。此前 Agent 架构调整未往演示库添加影片、评分、订单或优惠券；工作区中的影片资料可能由独立的数据导入流程更新。

## 调用流程

`POST /api/assistant/chat`（兼容 `/api/ai/chat`）继续只接收 `message` 和 `locale`。Flask 校验 CSRF、读取登录会话，然后交给 `cinema_ai/agent.py`。

1. 模型获得行为规则、工具 JSON Schema、近期对话、带来源与强度的本次条件、任务关系、待选择的恢复方案、候选序号和登录状态。
2. 模型可以直接回复，也可以返回原生 `tool_calls`。后端用固定工具注册表和 Pydantic 校验参数。
3. 工具在请求线程调用现有业务服务。模型请求在独立线程执行，期间不持有数据库连接或行锁。
4. 公开事实返回模型用于下一步查询或自然语言说明；订单、优惠券和费用等个人明细仅在后端/浏览器展示，模型只收到状态与可用序号。
5. 后端组装 `films / cinemas / cards / orders / coupons / previews / reschedule`；前端根据校验过的真实 ID 构造本站链接。模型的文本按纯文本展示，不执行 HTML 或模型 URL。

对于完整、明确的序号场次请求，例如“查第3部电影的场次”或“Show showtimes for the third movie”，先由 `cinema_ai/references.py` 识别，再用当前会话的影片候选顺序解析真实 ID，直接执行同一个 `search_screenings` 查询工具。这条路径不调用模型，缺人数时先保存选中影片再追问；补充人数后继续查该影片。已有日期、区域、预算等条件保留，场次和座位仍重新读取。无候选或序号越界时给出明确追问，不当成模型校验错误。包含日期、人数、否定或多个选项的复杂句子仍由模型理解。

模型的数字说明校验支持合法千位分隔符（例如 `3,352,918` 与已查询的 `3352918` 相同），未知数字仍触发事实模板降级。前端只显示一次后端错误说明。

此修复通过 221 项 Python/MySQL 回归；浏览器连接真实 DeepSeek 与演示库，验证“最近评分高的电影 → 查第3部电影的场次 → 两个人”，选中并保持 `Resident Evil (2026)`，返回该影片的三张场次卡片。截图见 `output/screenshots/film-reference-fixed.png`。序号越界、任务清空、会话隔离、已取消场次以及数字校验均有回归覆盖。

## 工具白名单

定义见 `cinema_ai/tool_types.py`，分发实现见 `cinema_ai/tools.py`。

| 工具 | 参数概要 | 读取边界 |
| --- | --- | --- |
| `search_films` | 条件更新、详情模式、影片候选序号、数量 1–3 | 影片/简介/类型/本站评分/评分人数/未来排片 |
| `search_screenings` | 条件更新、影片/影院/场次候选序号 | 可售场次、票价、可用座位与建议 |
| `search_cinemas` | 区域、名称、影片 | 启用影院及匹配排片 |
| `recover_search` | 后端生成的恢复令牌与选项 ID | 仅应用用户选择的有限调整，重新查询当前数据 |
| `get_rules` | 规则主题 | 版本化平台规则 |
| `get_my_orders` | 可选订单状态 | 当前登录顾客最近 3 笔订单 |
| `get_my_coupons` | 可选场次候选序号 | 当前顾客最近 3 张券及当前场次适用性 |
| `check_reschedule` | 本人订单序号、可选目标日期 | 原订单资格/费率/同影院同影片候选 |
| `preview_price` | 场次序号、普通/学生票数量、可选券/原订单序号 | 复用票价、折扣、补差与改签费逻辑 |
| `resolve_location` | 手动区域/已知地址、是否寻找最近 | 区级解析或地图页面入口，无模型定位权限 |

工具没有用户 ID、SQL、任意 URL、下单、占座、扣款、评分提交或优惠券核销参数。每次个人读取重新校验当前登录顾客和资源所有者，缓存序号不是授权凭证。

## 条件、排序与费用

- `Filters / FilterPatch` 新增 `genre / keyword / min_rating / rated_only / sort_by_rating / showing_only / recent / budget_minor / budget_scope / fare_type / require_contiguous`。同任务中字段缺省表示不修改；明确的新任务清除临时条件。`null` 仅在用户明确取消时清除可选条件。
- `film_id / cinema_id / screening_id` 是服务端通过候选引用解析的选择，不是模型可直接填写的字段。
- 预算金额为整数分，范围必须明确为 `per_ticket` 或 `total`；不明确时追问。默认按普通票、优惠前价格筛选，学生票须用户明确选择。混合票种和优惠券金额通过费用预览计算。
- 硬条件在截取前三名之前过滤；AI 与普通场次 API 共用 `cinema.catalog.search`。排序为连座优先、偏好区覆盖数、用户明确要求时的本站评分、开场时间、场次 ID。必须连座会排除分散方案。
- 同一轮的后续工具调用不能覆盖前面已经确认的条件；下一轮用户明确修改后才更新。无结果与查询失败分别返回。
- 后端 `booking.price` 校验真实占座后调用抽出的 `price_selection`；只读预览调用同一计算逻辑，但不生成持有座位记录、签名支付令牌或写操作。

## 状态、预算与降级

服务端内存保留最近 8 轮、当前条件、各类最多 3 个候选和最近任务。闲置 30 分钟清理。新对话清空全部状态，登录/退出轮换原站会话。适用于当前单进程演示；多进程部署需要共享存储和锁。

每轮最多 4 次模型调用、6 次业务工具调用，模型等待预算合计不超过配置的 10 秒。禁用 SDK 自动重试，重复工具请求提前停止。输入最多 2,000 字符，非流式。

初始模型解析失败保留条件；查询后解释失败、超时或出现未核实数字/交易成功声称等情况时，保留已查到的卡片并使用确定性说明。数字检查是额外防线，不能证明自然语言语义全部正确；权威价格、座位、评分和操作入口始终以结构化结果为准。日志仅记录工具名、状态、错误类别、用量和耗时。

新增 `PATCH /api/ai/preferences`：接收经过校验的条件补丁，需要 CSRF；前端手动选区与聊天共用条件，不调用模型。

## 数据限制

- 数据库暂无影片上映日期字段。“近期”明确解释为未来 14 天内有可售排片，不代表近 30 天首映；不查询外部实时榜单；当前评分来自统一的 10 分制数据。
- “轻松”等关键词只匹配已有类型/简介中的受支持词语，缺少资料时返回无匹配，不凭模型记忆扩写标签。
- 已有地图页面独立管理用户授权与坐标。AI 支持手动选区/已知地址与地图入口，尚无任意地标搜索工具，不自动接收地图位置。影院缺坐标时不能算距离。
- 本人订单/优惠券目前返回最近 3 条。需要更多历史记录时进入个人中心；聊天尚未实现翻页。
- 内置离线替身仅用于可重复测试，不能覆盖真实模型的所有语言表达。

## 全站悬浮助手（2026-10-24）

主站右下角显示 AI 悬浮球，点击展开聊天，收起后仍保留请求和回复。助手挂载在路由内容之外，页面内跳转时保留当前对话、推荐和输入草稿；点击卡片进入详情、选座、地图或登录页面会自动收起。旧 `#/assistant` 书签在首页展开助手；主导航不再设置独立助手页面。普通筛选继续使用首页搜索。

桌面显示右侧面板；600px 以下展开为接近全屏的面板，背景不可交互，键盘焦点限制在面板内，Escape 或关闭按钮收起并恢复焦点。中英切换、新对话、手动区域偏好、所有现有业务卡片及 DeepSeek 接入继续复用 `assistant.js`。登录/退出切换用户时中止旧请求并清理面板，避免展示上一账号的私人结果。聊天与草稿只保存在当前页面内存，不额外写入浏览器持久存储。

## 条件生命周期与无结果恢复（2026-10-24 更新）

保留 DeepSeek 原生工具调用与现有查询服务，新增 `condition_policy.py` 执行保守的条件更新规则。该条件管理阶段没有改动数据库表、评分或订单。

每个条件保存 `value / source / strength / scope / status / original_text`：来源区分 `user_explicit / model_inferred / system_default`，强度区分 `hard / soft / default`，状态区分 `active / relaxed / cleared`。当前实现的作用范围仅为 `current_task`；没有长期偏好保存机制，不能将模型推断写成用户长期偏好。默认北京、今天、普通票明确标为默认值；日期仅在场次查询中参与过滤。

查询参数增加 `task_action`（continue、modify、relax、new）、新任务的 `task_text` 和逐字段 `evidence`。证据必须是本轮用户消息的原文片段，不接受伪造引文。新任务清空临时条件及候选，规则问答自动建立独立任务；闲聊保留任务但不调用业务工具。修改人数保留区域、日期等未修改条件。清除或放宽既有硬限制必须有明确修改证据，单纯“再推荐一部”不会获得这项授权。选择其他城市会清除旧城市的区级条件，之后取消厅型不会切回北京。

评分处理：

- “评分高一点”只设置软排序偏好，不再生成 `min_rating=4` 或强制 `rated_only`。
- “评分至少 8 分”保留硬门槛；未评分影片不会被认定满足门槛。
- 软评分查询若没有任何已评分候选，先说明实际范围内都暂无评分，并提供恢复选项；随后普通推荐可放下这项软偏好，明确告知用户并返回未评分影片。
- 硬评分查询为空后，普通推荐继续展示恢复选项，用户选择后才删除评分过滤。
- 普通影片推荐排序使用当前可售排片、本站评分、评分人数；影片 ID 只用于最终并列，不宣称是个性化模型排名。
- 区域、厅型、类型和关键词可显式标为软偏好；先尝试满足全部偏好，无结果时才在保留全部硬限制的前提下提供替代，并说明哪些偏好未满足。该策略是有限回退，不是全局加权最优搜索。

查询无结果时返回 `status=needs_clarification`、`total=0`、`reason`、`active_filters` 和 `recovery={token,options}`。原因包含 `no_rated_movies / no_movies_meet_rating_requirement / no_matching_films / no_matching_screenings / outside_service_area`。后端只对有限字段试查取消单项条件后的结果，提供可验证的调整选项；不会编造更高预算或替换指定影片。没有可行的单项调整时保留要求，用户可另行提出新条件。

新增 `POST /api/ai/recovery`，需要原会话和 CSRF：

```json
{"token":"从上一条回复取得", "option_id":"include_unrated_movies", "locale":"zh"}
```

按钮不调用模型，后端校验令牌、当前条件快照和选项白名单，再重查最新数据库。令牌不能跨会话使用，修改条件、新任务、重置或已使用后失效。自然语言选择也可通过 `recover_search`；含糊的同意或普通推荐不能被模型当作删除硬限制的许可。
